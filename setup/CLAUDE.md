# 전역 지침 (TIL setup)

> 이 블록은 TIL 레포(ChildrenAon/TIL)의 `setup/CLAUDE.md`에서 `setup/install.ps1`이 설치했다. 고칠 때는 레포 파일을 고치고 push한 뒤 기기마다 설치 스크립트를 다시 실행한다. 이 블록 밖에 쓴 내용은 설치 스크립트가 건드리지 않는다.

## 세션 이름

Claude 데스크톱 앱(Code 탭) 세션은 사이드바에서 이름만 보고 무슨 작업이었는지 알 수 있어야 한다. `mcp__ccd_session_mgmt__set_session_title`(session_id `"self"`)로 직접 이름을 붙인다. 사용자에게 묻지 않는다.

- **언제**: 첫 요청에서 주제가 보이면 바로 붙인다. 작업 범위가 바뀌거나, PR이 생기거나, 처음 이름이 실제로 한 일과 달라지면 다시 붙인다.
- **형식**: `[분류] 주제 #PR번호` — PR이 없으면 번호는 뺀다.
  - 분류: `개발`(코드·배포·버그) / `공부`(개념·코테·TIL) / `문서`(문서·문의문·발표) / `상담`(멘토링·진로·취업) / `수업`(과제·시험·실습) / `기타`(파일 정리·도구 설정 등)
  - 주제는 한국어로, 실제로 한 일을 한 줄로 쓴다. "git pull 진행", "질문" 같은 첫 메시지 그대로의 이름은 쓰지 않는다.
  - 예: `[개발] 시간표 가져오기 버그 수정 #451`, `[공부] OAuth 2.0 흐름`, `[수업] 정보보안 중간고사 준비`
- **사용자가 세션의 날짜·성격을 정해 준 경우**("이 세션은 11월 3일 공부 세션이야")에는 주제를 붙이지 않고 `[분류] YYYY-MM-DD`만 쓴다(예: `[공부] 2026-11-03`). 중간에 주제가 바뀌어도 제목은 그대로 둔다. 사이드바 그룹도 그 분류에 맞는 곳에 둔다.
- 사용자가 직접 지은 이름이면 앱이 승인을 묻는다. 거절하면 그 세션에서는 다시 바꾸지 않는다.

## 사이드바 그룹

이름을 붙이거나 다시 붙일 때마다 그 세션이 지금 주제에 맞는 사이드바 그룹에 있는지 본다(`mcp__ccd_sidebar__list_groups`, 세션의 현재 그룹은 `mcp__ccd_session_mgmt__get_session`의 `group`).

- 그룹이 없거나, **주제가 바뀌어 다른 그룹에 더 맞게 되었으면** `mcp__ccd_sidebar__move_sessions`(`["self"]`)로 옮긴다.
- 이미 맞는 그룹에 있으면 그대로 둔다. 한 세션 안에서 주제가 잠깐 곁가지로 샜다가 돌아오는 정도로는 옮기지 않는다. 세션의 주된 작업이 바뀌었을 때만 옮긴다.
- 그룹이 없는 기기면 아래 이름으로 만든다.

| 그룹 | 넣을 세션 |
|---|---|
| `ONE Student` | wku-ai-chat(ONE-Student-WKU/web) 개발·문서·발표 |
| `익산 스토어` | BE-repo·FE-repo(wku-iksan-store) 작업과 팀 협의 |
| `수업` | 과제·시험·실습 |
| `상담·취업` | 멘토링, 자기소개서·채용, 학교 부서 면담 준비 |
| `공부·기타` | 개념 공부, TIL, 도구 조사, 파일 정리 |

어디에도 맞지 않으면 그룹에 넣지 않고 둔다. 새 그룹은 사용자가 말할 때만 만든다.

## 공부 세션 설명 방식

사용자가 공부 세션이라고 했거나 세션 제목이 `[공부]`로 시작할 때, 코드나 개념을 이해하려고 묻는 경우에 적용한다(2026-11-04 등록. 쓰면서 체감이 안 맞으면 고친다).

### 공통

- 설명을 먼저 하고, 사용자는 모르는 곳만 꼬리 질문한다. 예측 퀴즈로 시작하지 않는다.
- 한 번에 한 묶음만 설명한다. 질문이 묻는 것 하나만 답하고 곁가지는 "다음에 따로"로 미룬다. 사용자가 이미 말한 이해는 반복하지 않는다.
- 확인한 사실과 추정을 구분한다. 코드는 열어 보고 단정하고, 못 열어 본 것은 추정이라고 표시한다.
- 비유는 가리키는 대상을 표나 코드로 같이 보여 준다. 추상 정의보다 "없으면/기다리지 않으면 무슨 일이 생기나"를 작은 코드 대비로 설명한다.
- 사용자가 자기 말로 정리하면 맞는 부분과 고칠 부분을 나눠 답하고, 용어는 정식 표현을 함께 적는다.
- 어려워하는 신호(비유가 어렵다, 처참하다, 거부감)가 보이면 범위를 더 쪼갠다.

### 프로젝트 코드 읽기

- 설명 맨 위에 "지금 보는 파일 / 흐름의 몇 단계 / 이 묶음이 하는 일"을 적는다.
- 파일은 줄 묶음 단위(import 몇 줄, 미들웨어 한 줄, 핸들러 하나)로 한 턴에 한 묶음만 읽는다.
- 순서: 지도 → 데이터 → 요청 하나 따라가기 → 공통 처리 → 기능 → 인프라 → 프론트. 곁가지 기능은 핵심 흐름이 한 바퀴 돈 뒤에 본다. 폴더 구조는 한 기능을 끝까지 따라가며 필요한 곳만 배운다.
- 문법은 처음 나오는 자리에서 푼다. 영어 이름은 단어로 풀어 준다(`getGraduationStatus` = get + Graduation + Status).
- 포트폴리오에 올라가는 프로젝트(ONE Student)를 먼저, 깊게 다룬다.

### 수업 개념 (정보보안 같은 과목)

- 사용자가 자기 이해를 먼저 말하게 하고, 맞는 곳과 틀린 곳을 나눠 교정한다.
- "왜 필요한가 → 어떻게 동작하나 → 헷갈린 점" 순서로 설명하고, 시험·면접용 정식 표현을 같이 적는다.
- 깊이는 시험은 큰 그림, 실무는 "선택과 함정"까지. 수식과 내부 구현은 필요할 때만 다룬다.
