# 코테 — 오늘 문제 고르기와 기록

매일 "오늘 뭐 풀지"를 정하는 부담을 없애는 스킬이다. 시작할 때 Claude가 기록과 단계 규칙을 보고 오늘 문제를 골라 **프로그래머스 즐겨찾기 목록 = 오늘 풀 문제**가 되게 만든다. 공부가 끝나면 문제마다 세 줄 기록을 남긴다. 2026-11-23 사용자 결정으로 만들었다.

공부 방향(사용자와 정함):
- 문제 수보다 **유형**을 모은다. 한국어 문제(프로그래머스)로 기본기를 먼저 쌓고, 영어 문제(Codility 등)는 시험 전날에만 따로 본다.
- 문제마다 ① 입출력 예 → "무엇을 받아 무엇을 돌려주나" 한국어 한 줄 ② 손풀이를 한국어로 ③ 코드 ④ 막히면 힌트 → 풀이 → **풀이를 닫고 다시 짜기** ⑤ 다른 사람의 풀이 1~2개와 비교(정확성 → 제한사항 안에서 충분히 빠른가 → 실수할 곳이 적은가) ⑥ 세 줄 기록.
- 레벨마다 시간 기준이 다르다: Lv0 5~10분, Lv1 20~30분, Lv2 40분(시간을 재며). 넘으면 혼자 붙잡지 말고 힌트를 받는다.
- 언어는 JavaScript.

## 0. 레포 준비

1. 이 스킬 폴더의 `repo_path.txt`에 TIL 로컬 경로가 있다. 그 경로에서 `git pull --rebase`.
2. `coding-test/log.md`를 읽는다. 맨 위 「현재 단계」와 날짜별 기록, 「다시 풀 문제」가 있다.

## 1. 시작 모드 — 오늘 문제 고르기

### 1-1. 오늘 개수와 레벨 (단계 규칙)

| 단계 | 하루 구성 | 다음 단계로 가는 기준 |
|---|---|---|
| A. Lv0 | 코딩테스트 입문 Lv0 4문제 | 최근 Lv0 5문제를 모두 풀이 없이 10분 안에 |
| B. Lv1 섞기 | Lv0 2 + Lv1 1~2 | Lv1 3문제를 연속으로 혼자 30분 안에 |
| C. Lv1 + 고득점 Kit | Lv1 2 + 고득점 Kit 1 | Lv2 3문제를 연속으로 혼자 40분 안에 |
| D. Lv2 | Lv2 2 + 복습 | (Lv3는 사용자와 따로 정한다) |

- 「다시 풀 문제」 중 날짜가 오늘이거나 지난 것을 **먼저 1~2개** 넣고, 나머지를 새 문제로 채운다.
- 단계를 올릴 조건이 기록에서 확인되면 log.md의 「현재 단계」를 고치고 사용자에게 한 줄로 알린다. 내리는 것도 같다(사흘 연속 절반 이상을 풀이 보고 풀었으면 한 단계 내림).
- 사용자가 "오늘은 가볍게"처럼 양을 말하면 그 말을 따른다.

### 1-2. 문제 고르기

목록 주소(모두 JavaScript, 안 푼 문제만):

```
https://school.programmers.co.kr/learn/challenges?order=acceptance_desc&statuses=unsolved&levels=<레벨>&languages=javascript&bookmarked=false&page=<N>
```

- `levels`: 0, 1, 2 … / `order=acceptance_desc`: 정답률 높은 순 / `statuses=unsolved`: 안 푼 문제만(이미 "풀고 있는 문제"도 빠지지 않게 log.md와 한 번 더 대조).
- **필터가 기억된다(2026-11-23 확인).** 프로그래머스는 마지막에 쓴 필터(즐겨찾기만 보기, 상태, 레벨, 언어)를 기억해서, 주소에 없는 필터를 멋대로 붙인다. 그래서 `bookmarked=false`를 꼭 넣는다(빼면 즐겨찾기한 문제만 나와 후보가 1~2개로 줄어든다). 빈 값(`statuses=`)은 기억된 값으로 바뀌니 쓰지 않는다. 페이지를 연 뒤 `location.search`가 의도한 필터와 같은지 확인하고, 다르면 주소를 다시 연다.
- 목록은 화면에서 그려지므로(`fetch`로 HTML을 받아도 행이 없다) 페이지를 실제로 열어 읽는다.
- **여러 페이지를 본다.** 한 페이지는 20문제다. 이미 푼 문제·제외 조건을 빼고 나서 필요한 개수의 2배 이상 후보가 모일 때까지 `page`를 1, 2, 3 … 올린다. 행이 0개인 페이지가 나오면 거기서 멈춘다. 1페이지만 보고 끝내지 않는다.
- 행 읽기: `table tbody tr`의 제목·묶음(코딩테스트 입문 / 코딩 기초 트레이닝)·레벨·정답률, 링크 `/learn/courses/30/lessons/<id>`.
- 제외:
  - 「코딩 기초 트레이닝」의 "○○ 출력하기"처럼 `readline`으로 입력을 직접 읽어야 하는 문제(시험은 함수에 값이 들어오는 방식).
  - log.md에 이미 있는 문제(다시 풀 문제로 넣는 경우만 예외).
  - 정답률 40% 미만(단계 D 전까지).
- 섞기: 같은 날에 같은 종류(제목으로 보이는 주제: 사칙연산·조건문·배열·문자열·반복문 …)가 몰리지 않게 고른다. log.md에서 "틀린 이유"가 자주 나온 유형은 하나 더 넣는다.
- 단계 C부터 고득점 Kit는 이 순서로 한 유형씩 진행한다: 해시 → 스택/큐 → 정렬 → 완전탐색 → 탐욕법 → 깊이/너비 우선 탐색(DFS/BFS) → 동적계획법 → 힙 → 이분탐색 → 그래프. 유형 페이지는 `https://school.programmers.co.kr/learn/challenges?tab=algorithm_practice_kit`의 링크(`/learn/courses/30/parts/<id>`, 예: 해시 12077, 스택/큐 12081, 정렬 12198, 완전탐색 12230, 탐욕법 12244, DFS/BFS 12421, DP 12263, 힙 12117)에서 레벨이 낮은 것부터.

### 1-3. 즐겨찾기 (크롬)

`anthropic-skills:chrome-browser` 스킬을 먼저 읽고 Claude in Chrome으로 한다. 사람이 여는 속도로, 필요한 페이지만 연다.

1. **어제 목록 정리**: `https://school.programmers.co.kr/learn/challenges?bookmarked=true&statuses=solved,solved_with_unlock&page=<N>`(즐겨찾기 중 푼 문제, 레벨·언어 키는 빼서 모든 레벨)을 1페이지부터 행이 없을 때까지 보고, 나온 문제는 모두 즐겨찾기를 해제한다. log.md에 기록됐는데 아직 즐겨찾기에 남은 문제도 해제한다. 이어서 `bookmarked=true&statuses=unsolved`로 남은(아직 안 푼) 즐겨찾기를 확인해 오늘 개수에 포함한다.
2. **오늘 문제 추가**: 문제 페이지(`/learn/courses/30/lessons/<id>`)에서 제목 옆 즐겨찾기 아이콘을 누른다.
   - 아이콘은 `.challenge-bookmark` 두 개이고, 지금 상태가 아닌 쪽에 `hidden` 클래스가 붙는다. `title`(또는 `data-original-title`)이 "즐겨찾기 추가"인 쪽이 보이면 아직 안 된 것이고, 그것을 누르면 "즐겨찾기 해제" 쪽이 보이게 바뀐다. 해제는 반대로 한다.
   - 누른 뒤 보이는 쪽이 바뀌었는지 확인한다.
3. **확인**: 즐겨찾기 목록(`bookmarked=true&statuses=unsolved,solved,solved_with_unlock`)을 다시 열어 오늘 문제만 남았는지 본다.
4. **필터 되돌리기**: 마지막에 `https://school.programmers.co.kr/learn/challenges?bookmarked=false`를 한 번 열어, 사용자가 목록을 볼 때 즐겨찾기 필터가 켜진 채 남지 않게 한다. 사용자에게는 "즐겨찾기한 문제" 버튼을 누르면 오늘 목록이 나온다고 알린다.
5. 크롬 확장이 연결되지 않았거나 프로그래머스가 로그아웃 상태면, 즐겨찾기는 건너뛰고 목록과 링크만 보여 준다. 로그인은 사용자가 한다.

### 1-4. 오늘 목록 보여 주기

```
오늘 단계: A (Lv0) · 4문제 · 시간 기준 Lv0 10분

| 순서 | 문제 | 레벨 | 주제 | 비고 |
|---|---|---|---|---|
| 1 | [두 수의 합 구하기](https://school.programmers.co.kr/learn/courses/30/lessons/120802) | Lv0 | 사칙연산 | 다시 풀기 / 새 문제 |
```

그 아래에 한 줄씩: 막히면 "힌트만"이라고 하면 방향만 준다는 것, 다 풀면 "코테 기록"이라고 하면 된다는 것.

## 2. 푸는 동안 — 도울 때 지킬 것

- 먼저 **힌트만**: 어떤 유형인지, 손으로 풀면 어떤 순서인지까지만 말한다. 정답 코드는 사용자가 원할 때만 준다.
- 사용자 코드가 틀렸으면 맞는 부분과 고칠 부분을 나누고, 고칠 줄에 `// 이유` 주석을 단다.
- 두 가지 풀이가 있으면 위의 기준 세 가지로 비교해 어느 쪽이 나은지 결론까지 말한다.
- 새 문법은 가장 단순한 예로 먼저 보여 준다(전역 공부 세션 규칙).

## 3. 기록 모드 — "코테 기록"

1. 이 대화에서 푼 문제를 정리한다. 대화로 알 수 없는 것(걸린 시간, 풀이를 봤는지)은 한 번에 묶어서 짧게 묻는다.
2. `coding-test/log.md`의 오늘 날짜 아래에 문제마다 세 줄을 추가한다.

```
- [문제 제목](링크) · Lv0 · 주제 · 12분 · 혼자 / 힌트 / 풀이 봄
  - 핵심: (풀이의 핵심 한 줄, 문법이면 문법 이름)
  - 틀린 이유: (없으면 "없음")
```

3. 풀이를 봤거나 힌트를 받은 문제는 「다시 풀 문제」에 `- YYYY-MM-DD [제목](링크)` (3일 뒤 날짜)로 넣는다. 다시 풀어서 혼자 풀었으면 목록에서 지운다.
4. 1-1의 기준으로 「현재 단계」를 다시 판단한다.
5. 정답 코드는 넣지 않는다(다시 풀 때 답이 보이면 안 되고, 레포가 공개다). 문제 본문도 옮기지 않는다.
6. 커밋·push: `git add coding-test/log.md` → `coding: YYYY-MM-DD 문제 N개` → `git push`(거부되면 `git pull --rebase` 후 한 번 더).
7. 새로 이해한 개념이 있으면(예: 세미콜론 자동 삽입) `/til`의 `# 코테` 대제목으로 올리자고 한 줄로 제안한다. 올리는 건 `/til`이 한다.

## 4. 알리기

- 시작 모드: 1-4의 표와, 즐겨찾기를 추가·해제한 개수 한 줄.
- 기록 모드: 추가한 문제 수, 다시 풀 문제 수, 단계가 바뀌었으면 그 사실, 커밋 링크.
