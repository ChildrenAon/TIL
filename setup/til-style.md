# TIL 스타일 규칙

`/til` 초안을 보고 고쳐 달라고 한 것 중 다음 기록에도 적용할 것을 쌓아 두는 곳이다. `/til`은 매번 이 파일을 읽고, 여기 적힌 규칙을 스킬 기본 규칙보다 먼저 따른다.

- 한 줄에 규칙 하나, 끝에 추가한 날짜를 붙인다.
- 마음이 바뀌면 줄을 지우거나 고친다. 직접 고쳐도 되고, `/til` 중에 말로 해도 된다.

## 규칙

- 간결하고 읽기 쉽게 쓴다: 칸마다 불릿은 2~4개, 한 불릿은 한 가지 사실만 짧게, 같은 말을 두 칸에 반복하지 않는다. 덜 중요한 설명·비유·부연은 뺀다. (2026-11-03)
- 인과·변화는 문장 대신 기호로 짧게 쓴다: `M↑ → 공개키 연산 횟수↑ → 속도↓`, `개인키 ✗ / 공개키 ○`. 불릿은 명사구·단문 위주 노트체. (2026-11-03)

### 읽기 쉬운 구조 (강약을 둔다)

모든 줄이 같은 크기·같은 모양이면 눈이 멈출 곳이 없다. 아래를 지킨다.

- 항목 맨 위에 `> **한 줄 결론**: …` 인용 블록 하나. 이것만 읽어도 요점이 잡혀야 한다. 바로 아래 줄에 `정식 표현: …`. (2026-11-03)
- 소제목은 굵은 글씨 대신 `###`로 쓴다. 구간이 보이고 GitHub 목차에도 잡힌다. (2026-11-03)
- **굵게**는 핵심 용어에만, 불릿 하나에 1~2군데. 한 칸에 서너 군데 넘게 굵히지 않는다. 이탤릭·밑줄은 쓰지 않는다. (2026-11-03)
- 같은 축으로 견주는 내용(A일 때 / B일 때, 공격 / 막는 단계, 장치 / 방법 / 막는 것)은 불릿 여러 개 대신 **표**로 쓴다. (2026-11-03)
- 순서·구조·흐름은 **코드 블록 도식**(`text`)이나 **mermaid**(`flowchart`)로 쓴다. mermaid 라벨은 항상 큰따옴표로 감싸고, 줄바꿈은 `<br/>`로 한다. (2026-11-03)
- "헷갈린 점"은 `> [!WARNING]` 경고 박스로, 곁가지 참고는 `> [!NOTE]`로 쓴다. 한 항목에 박스는 2개까지. 남발하면 다시 균일해진다. (2026-11-03)
- 그날 항목이 2개 이상이면 하루 파일 맨 위(`# 날짜` 바로 아래)에 `> **오늘의 흐름**:` mermaid 도식을 둔다. 간선 라벨에 "왜 다음으로 넘어갔나(질문)"를 적는다. 항목을 추가하면 도식도 이어서 고친다. (2026-11-03)
- `[프로젝트]` 항목은 맨 위에 `> **지도에서 위치**:`(프로젝트 지도 링크 › 영역 › 기능)를 먼저 쓰고, 맨 끝에 같은 영역의 이전·다음 기록 링크를 단다. 프로젝트 지도 페이지(`projects/<이름>.md`)가 없으면 틀부터 만든다. (2026-11-03)
