## [개념] 전자서명
- 내 말로: M의 해시를 내 개인키로 암호화해 M과 같이 보냄 → 받는 쪽이 공개키로 풀어 직접 계산한 해시와 비교
- 정식 표현: 메시지 다이제스트 md를 송신자 개인키로 암호화한 값 ds. 무결성·출처 인증·부인방지

**왜 해시를 쓰나**
- M↑ → 공개키 연산 횟수↑ → 속도↓
- M → md(고정 길이)만 서명 → 서명 길이 고정
- 블록별 서명 → 순서 변경·삭제 공격 가능

**동작**
- 서명: `md = H(M)`, `ds = E(md, A_pr)`, 전송 `M ‖ ds`
- 검증: `H(M) = D(ds, A_pu)` → 합격 = 출처 인증 + 부인방지 + 무결성

**헷갈린 점**
- 검증은 개인키 ✗ / **공개키** ○ (개인키는 A만 가짐 → 공개키로 풀리면 A가 만든 값)
- 해시 = M의 지문, 서명 = 지문 보호. "해시=무결성, 공개키=출처 인증"으로 나눠 외우면 부정확
- Sign/Verify = DSA·ECDSA 포함 표기, E/D = RSA 기준

## [개념] 전자인증서
- 내 말로: 이 공개키가 이 사람 것이고 아직 믿어도 된다 → CA가 서명으로 보증한 문서
- 정식 표현: 공개키 인증서(X.509). CA가 소유자-공개키 결속(binding)에 한 전자서명

**왜 필요한가**
- 공개키는 공개 → 누구나 자기 키를 "A의 것"이라 주장 가능
- 검증키 바꿔치기: "키 바뀌었으니 교체" 요청 → 공격자 키 등록 → 공격자 서명이 A의 서명으로 통과
- 키 변경에 정당한 이유(개인키 유출, 알고리즘 약화, 주기적 갱신) → 공격이 통함
- 서명 = 누가 보냈나 / 인증서 = 검증 공개키가 그 사람 것인가

**동작**
- 신뢰하는 CA 공개키로 인증서 서명 검증 → 안의 공개키 신뢰
- 유효기간: 공개키 ✗ / **인증서** ○
- 만료 전 사고 → 폐지(CRL·OCSP). 유효 = 기간 안 + 폐지 안 됨
- 보증 범위 = 공개키-신원 연결, 그 사람의 신뢰성은 아님
