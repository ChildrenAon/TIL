# ONE Student 기능별 실행 순서

> 2026-11-07에 라우터에서 서비스 함수 내부까지 읽고 정리했다. 공부 순서는 [ONE Student 지도](one-student.md#공부-계획)를 따른다. 공부하며 다른 점을 찾으면 여기를 고친다.

## 핵심 기능

| # | 기능 | 실행 순서 |
|---|---|---|
| 1 | 챗봇 질문 → 답변 | 동시 요청 차단 → 입력 검사 → 내 대화 확인 → 하루 20개 한도 → 이전 대화 조회 → 질문 저장 → **AI로 검색어 정리** → **임베딩** → 학생·졸업 정보 동시 조회 → 연도 해석 → 규정 판단 → 자료 검색·과목 조회 동시 실행 → 우선순위로 합치기 → **AI 답변** → 답변 점검 → 저장 → 응답 |
| 2 | 졸업 현황 진단 | 로그인 확인 → 학생 조회 → 규정 엔진으로 요건 결정 → 들은 과목 조회(재수강 정리) → 이수구분 보정 → 학점 계산 → 교양·졸업인증 등 판정 → 신뢰도 결정 → 지난 결과와 비교 → 응답 |
| 3 | Google 로그인 | 약관 버전 검사 → `state` 저장 → Google로 이동 → 돌아와 `state` 비교·삭제 → **Google에서 토큰 받아 검증** → 이메일 인증 확인 → 학생 찾기(Google ID → 이메일 → 새로 가입) → 동의 기록 → 세션 재발급·저장 → 앱으로 이동 |
| 4 | 이메일 코드 로그인 | **요청:** 횟수 제한 → 이메일·동의 검사 → 재전송 확인 → 코드 생성(해시만 저장) → **메일 발송** / **확인:** 횟수 제한 → 입력·동의 검사 → 코드 검증 후 1회 사용 처리 → 학생 찾기·가입 → 동의 기록 → 세션 재발급·저장 |
| 5 | 성적 PDF 가져오기 | **분석:** 횟수 제한 → 파일 업로드 → 글자 추출 → 문서 종류 판별 → 개인정보 가리기 → 학기 5회 한도 예약 → **AI 추출** → 소계 대조 → 결과 응답(저장 안 함) / **확정:** 학생이 검토·수정 → 행마다 값 검사 → 새 과목 저장, 있던 과목은 빈 값만 채움 |
| 6 | 규정 문서 반영 | `main`에 문서 push → 승인 → Railway에 배포 → Cron Job이 시드 명령 실행 → 문서를 청크로 나눔 → **임베딩 전부 받기** → 트랜잭션으로 옛 문서 삭제·새 문서 저장 → 규정 조문 표 갱신 → Actions가 로그로 성공 판정 → 챗봇에는 최대 약 5분 뒤 반영 |

## 주요 기능

| # | 기능 | 실행 순서 |
|---|---|---|
| 7 | 약관 동의 | **새 로그인:** 체크 → 버전을 함께 전송 → 서버가 버전 비교 → 동의 기록 / **기존 계정:** `/me`에서 동의 필요 확인 → 동의 화면 → 버전 비교 → 기록 |
| 8 | 온보딩 | 학과·전공 목록 조회(로그인 없이 가능) → 입력 → 값·조합 검사 → 이미 완료했는지 확인 → 학생 정보와 완료 시각 저장 |
| 9 | 진로 탐색 | 하루 3회 한도 → 세션 생성 → 고정 답변 저장 → **AI 후속 질문** → 대화(최대 20턴) → 위기 표현 검사 → 후보 한도 확보 → **AI 후보 생성** → 진로 선택 → 남은 과목 계산 → **AI 로드맵** → 실제 있는 과목만 남기기 → 저장 |
| 10 | 커뮤니티 글 작성 | 제재 확인 → 값 검사 → 트랜잭션으로 글(승인 대기)·학과 저장 → 응답 / 뒤에서 Discord 알림·**AI 분류** → 관리자 승인 → 상태가 `approved`가 되면 공개 |
| 11 | 매칭 → 메일 중계 | 신청(트랜잭션) → 글쓴이 수락(트랜잭션으로 연결 주소 2개 생성·상태 변경) → 각자 상대의 연결 주소 조회 → 학생이 메일 발송 → **Resend 웹훅** → 서명 확인 → 대상·차단 확인 → 메일 내용 받기 → 첨부 받기 → 본문 정리 → **상대의 실제 주소로 발송** |
| 12 | 신고 → 제재 → 이의 제기 | 신고(트랜잭션, 중복 차단) → 뒤에서 Discord 알림·**AI 분류** → 관리자가 신고함 확인(이전 위반으로 제안 계산) → 제재 저장 → 글 삭제 → 신고 완료 → 정지된 학생의 이의 제기 → 관리자 답변 |
| 13 | 내 수강 과목 관리 | **추가:** 값 검사 → 개설 과목 확인 → 시간표 충돌 검사 → 과목 저장 → 시간표 저장 / **조회:** 재수강 정리 후 학점·평점 계산 |

## 보조 기능

| # | 기능 | 실행 순서 |
|---|---|---|
| 14 | 내 정보 수정·탈퇴 | **수정:** 값 검사(닉네임 중복 포함) → 보낸 칸만 저장 → 다시 조회 / **탈퇴:** 5분 안에 재인증했는지 확인 → 정지 중이면 재가입 차단 기록(해시) → 학생 삭제 → 세션 삭제 |
| 15 | 과목 검색 | 연도·학기 확인 → 학생·학과 조회(실패해도 계속) → 학기 과목 캐시 조회 → 검색어 순위 → 내 학과 우선 정렬 → 시간표 붙이기 → 응답 |
| 16 | 문의하기 | 값 검사 → 저장 → 응답 / 뒤에서 Discord 알림·**AI 분류** → 관리자 조회 → 필요하면 **AI 초안**(저장 안 함) → 답변 저장 → 학생이 내 문의에서 확인 |
| 17 | 공지사항 | 관리자가 작성(승인 없이 바로 게시) → 목록에서 새 공지 계산 → 안 읽은 수 조회 → 읽음 기록 |
| 18 | 기능 사용 통계 | 클릭 모으기 → 15초마다·탭을 벗어날 때 전송 → 허용 목록으로 값 정리 → 날짜·기능별 합계 저장(누가 눌렀는지 저장 안 함) → 관리자 조회 |

## 아직 안 읽은 부분

- 규정 엔진(`regulationEngine`)의 규칙별 세부
- `courseCounting`의 다전공 학점 판정 세부
- `koreanSearch`의 검색 순위 계산 세부
- `tryParseFullTranscriptLines` 등 성적표 파싱의 일부
- Railway의 실제 Start Command와 GitHub 승인자 설정(문서로만 확인)
